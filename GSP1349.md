# GSP1349 - Build godoctor, a Go MCP server, with the Antigravity CLI

This lab is prompt-driven: you paste shell blocks in one terminal and prompts into the Antigravity CLI (agy) in another. The AI writes the Go code. Your job is to check its work.

## Known lab traps/bugs (read first)

1. Every checkpoint only passes after a summary file is in the grading bucket (your project ID plus -grading). The checker looks for the file by name and nothing else gets you points. The model shown as "Model ID" is a placeholder; you type it once in Setup.
2. The lab tells you to exit the CLI and then give it the summary prompt. Do it the other way: give the summary prompt while agy is still open.
3. The lab says to click a "Proceed / Run" button. In the CLI there is no button: press Enter on "1. Yes, allow once".
4. In this tutorial the AI only writes each summary file. You upload it yourself with a paste block, so a failed AI upload can never cost you the checkpoint.
5. The AI is not deterministic. If it loops or invents things, press ESC and use the Rescue prompts at the end. Always run the test block yourself before moving on.
6. The checker lags: wait 30-60 seconds and click again.
7. Expect a lot of permission prompts: the Hello World step alone took about 40 approvals in a real run. "Yes, allow once" lets you read each action, which is the point of the lab. If you are short on time, the session-wide allow option in the same menu cuts the rounds, but then watch the output closely and press ESC if it drifts.
8. The AI may create extra files on its own (unit tests, a README). That is fine.
9. The AI can say "binaries compiled" while bin is empty (seen in a real run). The test blocks here rebuild bin/server and bin/client themselves, so trust the block, not the AI's summary.

Use two terminals for the whole lab. In the Cloud Shell Editor: View > Terminal, then the + icon for a second one. Terminal A runs agy. Terminal B is for the paste blocks.

## Task 2. Guidelines file, then launch agy

AGENTS.md is the rulebook the AI reads before it writes code. Rule 3 matters most: an MCP server on stdio must never print logs to standard output, or it corrupts the protocol stream.

Terminal B:

```bash
cd ~/godoctor
cat > AGENTS.md <<'EOF'
# Go Development Guidelines
All code contributed to this project must adhere to the following principles.

## 1. Formatting
All Go code **must** be formatted with `gofmt` before being submitted.

## 2. Naming Conventions
- **Packages:** Use short, concise, all-lowercase names.
- **Variables, Functions, and Methods:** Use `camelCase` for unexported identifiers and `PascalCase` for exported identifiers.
- **Interfaces:** Name interfaces for what they do (e.g., `io.Reader`), not with a prefix like `I`.

## 3. Error Handling
- Errors are values. Do not discard them.
- Handle errors explicitly using the `if err != nil` pattern.
- Provide context to errors using `fmt.Errorf("context: %w", err)`.
- **Use `os.Stderr` or `log` standard library for debug prints.** Do NOT use standard output (`fmt.Println`) for logging, as this pollutes the JSON-RPC stream used for `stdio` transport and crashes the connection.

## 4. Simplicity and Clarity
- "Clear is better than clever." Write code that is easy to understand.
- Avoid unnecessary complexity and abstractions.
- Prefer returning concrete types, not interfaces.

## 5. Documentation
- All exported identifiers (`PascalCase`) **must** have a doc comment.
- Comments should explain the *why*, not the *what*.

## 6. Project structure
- cmd/ contains source code for target binaries (e.g. server, client)
- internal/ contains source code for packages not meant to be exported (e.g. internal/tools/hello)
- bin/ contains the compiled binaries
- At the root place README.md, go.mod and go.sum
EOF
cp AGENTS.md GEMINI.md
grep -c '^## ' AGENTS.md
cmp AGENTS.md GEMINI.md && echo same
cat ~/project
```

You should see 6, then same, then your project ID (you need it in a moment).

## Task 3a. Hello World MCP server

Paste this prompt into agy (Terminal A). Press Enter on "1. Yes, allow once" each time it asks.

```text
Your task is to create a Model Context Protocol (MCP) server that exposes a "hello_world" tool. This tool, when called, should return the message "Hello, MCP world!"

For the MCP implementation, you should use the official Go SDK for MCP (github.com/modelcontextprotocol/go-sdk/mcp) and use the stdio transport.

TODO:
- Create the main.go file in the `./cmd/server` directory
- Download the dependency: `go get github.com/modelcontextprotocol/go-sdk/mcp`
- Inspect the documentation of the SDK: `go doc github.com/modelcontextprotocol/go-sdk/mcp`
- Build a `server` command that supports stdio transport only
- Build a `client` command that connects to the server over command transport to test the server

Acceptance Criteria:
- `./bin/client --list-tools` returns the list of server tools including "hello_world"
- `./bin/client --call-tool "hello_world"` returns the output "Hello, MCP world!"
```

Why this prompt works: it has a spec with constraints, a pointer to documentation, and acceptance criteria the AI can test itself.

When it says it is done, test it yourself in Terminal B:

```bash
cd ~/godoctor
mkdir -p bin
go build -o ./bin/server ./cmd/server && go build -o ./bin/client ./cmd/client
ls cmd bin
./bin/client --list-tools
./bin/client --call-tool "hello_world"
```

You should see client and server under both cmd and bin, then hello_world in the list and the line Hello, MCP world! The block builds the binaries itself because the AI sometimes reports them as compiled and leaves bin empty. If the build or the calls fail, tell agy exactly what you saw and ask it to fix it.

Still in agy (do not exit), paste the summary prompt:

```text

- The steps taken to build and test the server and client using stdio transport
- The output of testing `./bin/client --call-tool "hello_world"`

Only write the file. I will upload it myself.
```

Terminal B - upload:

```bash
cd ~/godoctor
gcloud storage cp summary_task1.md `cat ~/bucket`
gcloud storage ls `cat ~/bucket`
```

You should see summary_task1.md listed in the bucket.

Check my progress: Create Hello World Tool

If the check says "Could not find file summary_task1.md in Cloud Storage bucket", the upload block above was skipped or failed. Run it again and read its output.

## Rescue prompts (when the AI gets stuck)

Press ESC first, then send whichever fits:

```text
Use the `go doc` shell command to discover the api for the go-sdk library.
```

```text
Do not use read_file on files outside this folder. Use cat and ls through the shell instead.
```

```text
Add more verbose logging to stderr and put more context in the error messages, then run the acceptance tests again.
```

```text
Use this reference implementation as a guide: https://github.com/danicat/godoctor
```

Other fixes: /model switches model if you get an API capacity error. /compress shrinks a long, confused session. /clear wipes the session if it keeps forcing a wrong path.
